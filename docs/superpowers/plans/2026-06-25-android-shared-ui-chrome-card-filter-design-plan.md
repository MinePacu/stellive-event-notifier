# Android Shared UI Chrome, Card, And Filter Design Plan

## 1. 목적

이미지 1~5의 요구사항을 Android 앱의 홈, 라이브, 노래, 굿즈/행사 화면에 일관되게 적용한다.

- 본문 상단의 큰 페이지 제목·설명 영역을 제거한다.
- 페이지 제목은 기존 상단 바에서 처리한다.
- 노래 검색을 별도 화면으로 분리한다.
- 필터를 상단 바 바로 아래의 공용 필터 영역으로 통합한다.
- 카드 표면, 모서리, 외부 섹션 제목을 공용 디자인 정책으로 통합한다.
- 스크롤 시 상단 바를 축약하되 굿즈/행사 상세 화면은 제목을 유지한다.

제공 이미지는 파란 사각형과 설명 문구로 지정한 변경 위치만 해석한다. Samsung Health의 그래프, 운동 기록, 카드 구성, 아이콘, 색상, 버튼 배치와 고유 UI는 참조하거나 복제하지 않고 현재 프로젝트 색상과 자체 구성 요소만 사용한다.

## 2. 현재 구조 분석

Serena 심볼·참조 검색으로 확인한 주요 구조는 다음과 같다.

- `MainActivity.startScreen()`
  - 모든 화면의 본문에 `screenTitle()`과 `screenCopy()`를 삽입한다.
  - 이미지 1에서 삭제 대상으로 표시한 큰 제목·설명 영역의 직접 원인이다.
- `MainActivity.updateTopBarScrolled()`
  - 스크롤 시 `collapsedTitle`, `collapsedRole`, divider의 alpha를 표시한다.
- `MainActivity.updateNavigationChrome()`
  - `MainUiPolicy.showsTopBarText()`에 따라 상단 바 제목 그룹과 설정 버튼을 표시한다.
- `MainActivity.baseCard()`
  - 카드 배경, 테두리, 반경을 한 곳에서 정의하지만 카드 외부의 날짜·섹션 제목과 카드 변형 정책은 분산되어 있다.
- `MainActivity.renderSongs()`
  - 본문 내부에 검색 카드와 두 줄 필터를 직접 삽입한다.
- `MainActivity.songFilterRow()`, `liveStatusChips()`, `staticChips()`
  - 화면마다 개별 `HorizontalScrollView`와 Chip 구성을 만든다.
- `activity_main.xml`
  - 오버레이 상단 바와 본문 ScrollView가 분리되어 있다.

`baseCard()` 참조는 노래, 라이브, 기록, 설정, 이벤트 등 다수 카드에 걸쳐 있으므로 카드 정책 변경은 개별 카드 전체를 직접 수정하지 않고 공용 스타일 계층을 통해 적용해야 한다.

## 3. 범위

### 포함

- Android 앱의 홈, 라이브, 노래, 굿즈/행사 목록 화면.
- 노래 검색 전용 화면.
- 공용 상단 바 축약 동작.
- 공용 카드 표면·모서리·섹션 레이블.
- 공용 필터 스트립과 가로 스크롤 표시.
- 관련 UI 정책 및 상태 전환 테스트.

### 제외

- iOS UI 변경.
- 백엔드 API 및 DB 변경.
- 굿즈/행사 상세 화면의 제목 숨김.
- 설정 계층의 정보 구조 변경.
- Samsung Health와 동일한 그래프, 아이콘, 자산 또는 컴포넌트 복제.
- 기존 알림·음악·행사 데이터 정책 변경.

## 4. 공용 UI 아키텍처

### 4.1 `MainScreenChromePolicy`

화면별 상단 바와 본문 헤더 표시 여부를 결정하는 순수 정책이다.

```kotlin
data class MainScreenChromeSpec(
    val showExpandedBodyHeader: Boolean,
    val showTopBarTitleAtRest: Boolean,
    val keepTopBarTitleWhenScrolled: Boolean,
    val showSettingsAction: Boolean,
    val showSongSearchAction: Boolean,
)
```

기본 정책:

| 화면 | 본문 큰 제목 | 정지 상태 상단 제목 | 스크롤 후 제목 | 설정 | 검색 |
|---|---:|---:|---:|---:|---:|
| 홈 | 숨김 | 표시 | 숨김 | 표시 | 숨김 |
| 라이브 | 숨김 | 표시 | 숨김 | 표시 | 숨김 |
| 노래 | 숨김 | 표시 | 숨김 | 표시 | 표시 |
| 굿즈/행사 목록 | 숨김 | 표시 | 숨김 | 표시 | 숨김 |
| 노래 검색 | 숨김 | 표시 | 표시 | 숨김 | 숨김 |
| 굿즈/행사 상세 | 기존 상세 구성 유지 | 표시 | 표시 | 숨김 | 숨김 |
| 설정/하위 설정 | 기존 구성 유지 | 표시 | 표시 | 화면별 기존 정책 | 숨김 |

상단 제목은 페이지 식별을 위해 화면 진입 시 보이지만, 루트 화면에서 아래로 스크롤하면 콘텐츠 공간 확보를 위해 숨긴다. 뒤로 가기 버튼과 우측 액션은 유지한다.

### 4.2 `HubCardStyle`

카드의 역할을 세 가지로 한정한다.

```kotlin
enum class HubCardStyle {
    STANDARD,
    COMPACT,
    INTERACTIVE,
}
```

공통 원칙:

- 둥근 모서리와 0 elevation을 사용한다.
- 다크 모드는 현재 `hub_card`보다 배경과 약간 구분되는 회색 계열을 유지한다.
- 라이트 모드는 `hub_background`와 구분되지만 과도하게 밝거나 두꺼운 테두리를 사용하지 않는다.
- 모든 카드에 동일한 stroke를 강제하지 않고 역할에 따라 stroke를 생략할 수 있다.
- 클릭 가능한 카드는 ripple, focusable, 접근성 설명을 유지한다.
- 카드 안에 제목을 반복하지 않고, 날짜·그룹명·섹션 제목은 카드 바깥 좌측 위에 배치한다.

기존 `baseCard()`는 제거하지 않고 `hubCard(style)`의 호환 래퍼로 단계적으로 전환한다.

### 4.3 `SectionHeaderView`

날짜, “최근 알림”, “지금 라이브”처럼 카드 묶음을 설명하는 제목을 카드 외부에 배치한다.

```kotlin
data class SectionHeaderSpec(
    val title: String,
    val trailingText: String? = null,
)
```

- 왼쪽 정렬.
- 카드와 독립된 작은 굵은 글씨.
- 날짜 범위는 기존 `CalendarUiPolicy`의 포맷 결과를 재사용한다.
- 이벤트 카드 내부의 동일 제목은 제거하지 않되 외부 섹션 제목과 중복되는 메타 문구만 줄인다.

### 4.4 `TopFilterStrip`

화면별 필터를 상단 바 아래에 고정된 공용 영역으로 표시한다.

```kotlin
data class TopFilterOption(
    val id: String,
    val label: String,
)

data class TopFilterGroup(
    val id: String,
    val options: List<TopFilterOption>,
    val selectedId: String,
)
```

동작:

- 필터 그룹이 하나이고 선택지가 3개 이하면 가로 폭을 동일하게 나눈다.
- 선택지가 4개 이상이면 한 화면에 약 3개가 보이도록 최소 폭을 적용한다.
- 초과 항목은 가로 스크롤로 탐색한다.
- 스크롤 가능한 경우 우측 가장자리에 작은 그라데이션/chevron 표시를 둔다.
- 선택 상태는 기존 `hub_accent_soft`와 텍스트 강조로 표현한다.
- 노래 화면은 기수와 타입을 두 개의 그룹으로 표시한다.
- 굿즈/행사는 기존 분류 필터를 실제 선택 가능한 상태로 연결하되 데이터 필터링 정책은 기존 `MockHubRepository`/서버 조회 경계를 유지한다.

공용 필터 스트립은 콘텐츠 ScrollView 안에 넣지 않고 상단 바 아래 별도 컨테이너에 둔다. 따라서 목록을 스크롤해도 필터가 유지된다.

## 5. 화면별 설계

### 5.1 홈

- 본문의 “홈” 제목과 설명을 제거한다.
- 상단 바에는 “홈”과 설정 버튼을 표시한다.
- 기존 서버 상태 스트립은 유지하되 작은 상태 요소로 취급한다.
- “지금 라이브”, “최근 커버곡”, “최근 알림”, “마감 임박 굿즈/행사”는 외부 섹션 제목과 카드 묶음으로 표시한다.
- 홈에는 필터 스트립을 표시하지 않는다.

### 5.2 라이브

- 본문 큰 제목과 설명을 제거한다.
- 현재 라이브 상태 필터를 상단 고정 필터 스트립으로 이동한다.
- 서버 상태 스트립은 목록 상단의 작은 상태 요소로 유지한다.
- 멤버 카드는 공용 `INTERACTIVE` 카드 스타일을 사용한다.

### 5.3 노래

- 본문 큰 제목과 설명을 제거한다.
- 본문 검색 카드를 완전히 제거한다.
- 상단 바 우측에서 설정 버튼 왼쪽에 검색 아이콘을 표시한다.
- 검색 아이콘을 누르면 `SONG_SEARCH` 화면으로 이동한다.
- 기수와 타입 필터는 상단 고정 필터 스트립으로 이동한다.
- 멤버 선택 카드는 결과 목록 위의 작은 selector row로 유지한다.
- 노래 목록과 페이지네이션은 기존 클라이언트 정책을 유지한다.

### 5.4 노래 검색

- 상단 바에 뒤로 가기 버튼과 “노래 검색” 제목을 표시한다.
- 검색 입력은 화면 최상단에 한 번만 생성한다.
- 기존 debounce와 `normalizedSongQuery()`를 재사용한다.
- 검색 결과는 기수·타입·멤버 선택 상태를 그대로 적용한다.
- 검색 화면을 닫아도 검색어 유지 여부는 기존 `selectedSongQuery` 상태를 따른다.
- 검색 입력 포커스 해제 시 뷰를 동기적으로 제거하지 않는다.

### 5.5 굿즈/행사 목록

- 본문 큰 제목과 설명을 제거한다.
- 요약 숫자 카드 영역은 이미지 1의 삭제 요구에 따라 제거한다.
- 카테고리 필터를 상단 고정 필터 스트립으로 이동한다.
- 달력과 날짜별 카드 목록은 유지한다.
- 날짜/기간 제목을 카드 외부 좌측에 표시한다.

### 5.6 굿즈/행사 상세

- 이미지 4의 예외에 따라 제목 숨김 정책을 적용하지 않는다.
- 뒤로 가기 버튼과 이벤트 제목을 상단 바에 계속 표시한다.
- 상세 카드의 데이터 구조는 변경하지 않는다.

## 6. 스크롤과 상단 바

- 루트 화면에서 `scrollY <= threshold`이면 제목을 표시한다.
- 루트 화면에서 `scrollY > threshold`이면 제목 텍스트만 숨긴다.
- 뒤로 가기, 설정, 검색 버튼은 숨기지 않는다.
- 노래 검색, 설정, 굿즈/행사 상세 화면은 스크롤 상태와 무관하게 제목을 유지한다.
- 기존 `topBarFadeSpace`는 공용 필터 컨테이너 높이와 함께 계산하도록 조정한다.
- 배경은 현재 `bg_top_bar_glass` 그라데이션을 유지한다.

## 7. 접근성

- 검색 버튼에는 `노래 검색` content description을 사용한다.
- 필터 선택에는 checked 상태와 그룹 이름을 접근성 텍스트로 제공한다.
- 가로 스크롤 표시가 실제 버튼처럼 읽히지 않도록 장식 요소로 처리한다.
- 최소 터치 영역은 44dp 이상을 유지한다.
- 다크/라이트 모드 모두 텍스트 대비를 기존 색상 토큰 수준 이상으로 유지한다.

## 8. 상태 및 오류 처리

- 필터 선택은 기존 화면 상태 필드를 갱신하고 필요한 화면만 다시 렌더링한다.
- 노래 검색 debounce는 화면을 떠날 때 취소한다.
- 서버 로딩/오프라인 상태는 기존 `serverStatusStrip()`과 fallback 정책을 유지한다.
- 데이터가 없을 때는 카드 디자인 변경과 무관하게 기존 empty-state 문구를 사용한다.
- 가로 필터 스크롤 위치는 같은 화면의 재렌더링 중 가능한 한 보존한다.

## 9. 완료 기준

- 네 루트 화면에서 본문 큰 제목·설명 영역이 보이지 않는다.
- 노래 본문에 검색 입력이 없고 상단 검색 버튼을 통해 검색 화면으로 이동한다.
- 라이브, 노래, 굿즈/행사 필터가 상단 바 아래 공용 영역에 표시된다.
- 4개 이상의 필터는 가로 스크롤 가능하며 스크롤 가능 표시가 보인다.
- 일반 루트 화면은 스크롤 시 제목이 숨겨지고 상세/검색/설정 화면은 제목을 유지한다.
- 카드 모서리, 배경, 외부 섹션 제목이 공용 정책으로 일관되게 표시된다.
- 기존 데이터 조회, 페이지네이션, 알림 정책, 상세 화면 동작에 회귀가 없다.
