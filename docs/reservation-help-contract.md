# 예약·구매 도움말 공통 계약

Android와 iOS의 예약·구매 도움말은 플랫폼별 네이티브 UI를 사용하되 아래 의미 구조를 동일하게 유지한다.

## 도움말 상태

| 상태 ID | 표시 조건 | 톤 | 기본 동작 |
| --- | --- | --- | --- |
| `getting_started` | 활성 임시 항목과 저장 내역이 없음 | `info` | 3단계 사용 흐름 안내 |
| `pending` | 만료되지 않은 임시 항목이 하나 이상 있음 | `warning` | `view_pending` |
| `manage_records` | 임시 항목은 없고 저장 내역이 있음 | `info` | 예정 내역이 있으면 `view_upcoming` |

`pending` 상태는 활성 임시 항목 수와 가장 먼저 만료되는 항목의 대략적인 남은 시간을 표시한다.

## 동작 ID

| 동작 ID | 대상 |
| --- | --- |
| `view_pending` | 예약·구매 목록의 확인 필요 영역 |
| `add_without_link` | 가장 먼저 만료되는 활성 임시 항목의 추가 화면 |
| `view_upcoming` | 예약·구매 목록의 예정된 내역 영역 |
| `edit_current_record` | 현재 상세 내역의 수정 화면 |
| `view_existing_record` | 중복 링크가 연결된 기존 내역 상세 |

현재 상태에서 대상이 존재하지 않는 동작은 표시하지 않는다.

## 임시 항목 만료 표시

임시 항목의 만료 정책은 최대 2시간으로 유지한다. 화면에는 정확한 초 단위 카운트다운 대신 다음 안정 구간을 사용한다.

- 60분 이상: 올림한 시간 단위
- 10분 이상 60분 미만: 5분 단위로 올림
- 2분 이상 10분 미만: 1분 단위로 올림
- 2분 미만: `곧 자동 정리`
- 만료됨: 활성 임시 항목과 도움말 상태에서 제외

화면 재진입 또는 상태 갱신 때 남은 시간을 다시 계산한다.

## 내역 일정 스냅샷

임시 항목과 저장 내역은 공식 행사 일정을 스냅샷으로 저장한다. 판매·예매 시작 같은 보조 회차 시각은 내역 일정으로 쓰지 않는다.

1. 링크가 연결된 회차가 `main_window`면 그 회차의 시작·종료 시각을 저장한다.
2. 그 밖의 회차이거나 회차가 없으면 취소되지 않은 대표 회차(`isPrimary`)의 시작·종료 시각을 저장한다.
3. 대표 회차가 없으면 행사의 `startsAt`/`endsAt`을 저장한다. 둘 다 없으면 날짜 없는 내역이다.
4. 스냅샷은 선택한 회차의 `timePrecision`(`date`/`datetime`)과 `timezone`을 함께 저장한다. 값이 없는 기존 스냅샷은 `datetime`, `Asia/Seoul`로 해석한다.

기존 내역은 자동 보정하지 않는다.

## 공식 정보 변경 판단

최신 행사 정보에서 위 스냅샷 규칙으로 일정을 다시 고른 뒤, 제목·시작·종료·장소 중 하나라도 저장된 스냅샷과 다르면 공식 정보 변경으로 표시한다. 내역에 연결된 `main_window` 회차가 취소됐거나 행사가 취소되면 취소로 표시한다. 어떤 경우에도 사용자 상태와 수정값은 자동으로 바뀌지 않는다.

## 목록 구분

| 상태 | 구분 |
| --- | --- |
| `confirmed`, `pending_confirmation` | 일정 기준으로 예정/지난 구분 |
| `cancelled`, `refunded`, `completed` | 항상 지난 내역 |

- 기준 시각은 유효 종료 시각이며, 없으면 유효 시작 시각이다. 사용자 수정값이 있으면 수정값이 우선한다.
- 기준 시각이 없으면 예정 내역이다.
- 기준 시각이 스냅샷의 `date` 정밀도 값이면 해당 `timezone`에서 그 날짜가 끝나는 시점(다음 날 0시)까지 예정이다. 사용자 수정값은 `datetime`으로 취급한다.
- 그 밖에는 현재 시각이 기준 시각보다 앞설 때만 예정이다.
- 예정 내역은 유효 시작 시각 오름차순으로 정렬하고 날짜 없는 내역은 마지막에 둔다.
- `date` 정밀도 값은 화면에 시각 없이 날짜만 표시한다.
