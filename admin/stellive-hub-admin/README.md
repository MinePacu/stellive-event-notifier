# Stellive Hub Admin

Web admin console for the Stellive Hub API (hub events, announcements,
operations, audit, settings). It replaces the backend's legacy inline-HTML
admin console. The same frontend is intended to be packaged as a macOS
desktop app with Tauri v2 (`src-tauri/`).

Stack: Vite, React, TypeScript, shadcn/ui, Tailwind CSS, TanStack Router,
TanStack Query, zustand, react-hook-form + zod.

## Attribution

The UI shell is based on [satnaing/shadcn-admin](https://github.com/satnaing/shadcn-admin)
(MIT). The upstream license text is kept in [`LICENSE-shadcn-admin`](./LICENSE-shadcn-admin).
Demo features, Clerk, and sample data from the template were removed.

This is an unofficial fan project. Do not add official Stellive logos, member
images, or other brand assets; use neutral text and lucide icons.

## Install

Requires Node.js and pnpm.

```sh
cd admin/stellive-hub-admin
pnpm install
```

Optional: to keep the pnpm store and virtual store off the project disk,
create a machine-local `.npmrc` in this directory (it is gitignored), e.g.

```ini
store-dir=/path/to/caches/pnpm-store
virtual-store-dir=/path/to/caches/projects/stellive-hub-admin/.pnpm
node-linker=isolated
package-import-method=hardlink
```

`vite.config.ts` already allows the dev server to read from an external
virtual store and dedupes packages that rely on project-level resolution.

## Develop

```sh
pnpm dev      # http://localhost:5173/admin/
```

The dev server proxies `/v1` to the backend at `http://localhost:4000`
(override with `ADMIN_DEV_BACKEND_ORIGIN`), so the admin session cookie works
same-origin.

## Build

```sh
pnpm build    # tsc -b && vite build -> dist/
pnpm lint
```

The web build uses base `/admin/`; the backend serves `dist/` at `/admin`.
When the Tauri CLI runs the build (`TAURI_ENV_PLATFORM` is set), the base is `/`.

## macOS app (Tauri)

The same React app can be packaged as a native macOS app with Tauri v2
(`src-tauri/`). API calls go through the Rust HTTP plugin, so the operator
enters the server URL and an admin token instead of using the web cookie.

Prerequisites: Rust (`rustup`, stable) and Xcode Command Line Tools
(`xcode-select --install`). On a machine with little internal disk, point the
Rust caches at an external volume before running any cargo/tauri command:

```sh
export CARGO_HOME=/Volumes/Data_Backup/caches/cargo-home
export CARGO_TARGET_DIR=/Volumes/Data_Backup/caches/projects/stellive-hub-admin-tauri-target
export CARGO_BUILD_JOBS=3
export PATH="$HOME/.cargo/bin:$PATH"
```

```sh
pnpm tauri dev            # dev window against the Vite dev server (port 5173)
pnpm tauri build          # release build (.app and .dmg)
pnpm tauri build --bundles app   # .app only
```

Output: `$CARGO_TARGET_DIR/release/bundle/macos/Stellive Hub Admin.app` (and
`bundle/dmg/*.dmg`). Without `CARGO_TARGET_DIR` it is
`src-tauri/target/release/bundle/`, which is git-ignored.

First run: the sign-in page asks for the server URL (for example
`https://hub.example.com`) and the admin token. The URL is remembered in
`localStorage`; the token lives in `sessionStorage` only.

The app is unsigned and not notarized. On first launch macOS Gatekeeper blocks
it: right-click the app, choose Open, then confirm (or run
`xattr -dr com.apple.quarantine "Stellive Hub Admin.app"`). The window icon is
a neutral placeholder, not a brand asset.

## Authentication

- Web: sign in with the admin console token (`POST /v1/admin/session` sets an
  HTTP-only session cookie). `/v1/admin/*` calls use the cookie.
- Desktop (Tauri): the server URL is stored in `localStorage`; the admin token
  is kept in `sessionStorage` and sent as `Authorization: Bearer`.
- `/v1/internal/*` calls use a separate internal API token entered in
  Settings. It is kept in `sessionStorage` only.

## Project layout

- `src/lib/api.ts` — `apiFetch` / `api.*` / `ApiError` / `describeApiError`
- `src/lib/session.ts` — `checkAdminSession`, `signIn`, `signOut`
- `src/lib/i18n/` — `useT()`, `t()`, locale store; messages split per feature in `messages/`
- `src/stores/` — auth/token state and console preferences
- `src/features/<page>/` — one folder per page
- `src/routes/` — TanStack Router file routes (`routeTree.gen.ts` is generated by the Vite plugin and committed)
